# Risk Gate and Security Checks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Port the lwtv-underscores risk gate and security checks into this repo, so a high-risk PR can't merge into `release/**` or `production` without Mika's review of that exact commit.

**Architecture:** `risk_tier.py` classifies a PR's changed files against two pattern lists read at the base commit. `risk-tier.yml` turns that into a pass or fail, and a listed human's `human-reviewed` label becomes a per-SHA `human-review` commit status. CI gains Pint, lockfile checks, the gate's tests, and a `security` job that runs no PR code. A ruleset, set after merge, makes the checks required.

**Tech Stack:** GitHub Actions, Python 3 stdlib (`unittest`), Laravel Pint, composer/npm audit, gitleaks 8.30.1, OSV-Scanner reusable workflows v2.7.1, Dependabot.

**Spec:** `docs/superpowers/specs/2026-11-23-risk-gate-design.md`

**Source repo:** `/Users/ipstenu/Development/lezwatch/lwtv-underscores` (read only; never edit it). Paths below written `U:` are relative to it.

## Global Constraints

- Every `uses:` is pinned to a full commit SHA with the version in a comment, reusing the SHAs lwtv-underscores pins (checkout `3d3c42e5…` v7.0.1, setup-php `eb7c497e…` 2.40.0, setup-node `949feb24…` v7.1.0, osv-scanner-action `32d3cd48…` v2.7.1).
- Every `actions/checkout` has `persist-credentials: false`.
- Workflow `permissions:` stay least-privilege: `contents: read` unless a job needs more, as in the source.
- Required check names, exactly: `PHPUnit`, `Docker build`, `security`, `risk-tier`, `scan-pr / osv-scan`.
- Protected branches: `production` and `release/**`.
- `HUMAN_REVIEWERS` = `ipstenu`.
- `risk_tier.py` is copied byte-for-byte; any change to it is a ledgered ruling.
- The PHP version in CI stays `8.4`, matching the container.
- Nothing is changed in GitHub settings (labels, variables, rulesets) without Mika's go-ahead in chat (Task 6).

## Review Focus

1. **First-PR bootstrapping.** The lists don't exist on the base, so `risk_tier.py` falls back to the PR's own copies. Expected: the PR classifies as high (it touches `.github/*`) and needs a manual review. Pinned by the local run in Task 2.
2. **OSV PR scan on the first PR.** The reusable PR workflow also scans the base with `--config=.github/osv-scanner.toml`, which the base doesn't have yet, so that check is expected to error on this PR only. Expected: it's not required yet, and it passes on the next PR. Noted in the PR body (Task 5).
3. **A file under an allowed folder that is a harness file** (`tests/TestCase.php`, `resources/js/sw.js`). Expected: high, because the high list wins. Pinned in Task 1's `test_listed_file_inside_an_allowed_area_is_still_high`.
4. **A renamed high-risk file** (`docker/php/entrypoint.sh` moved to `docs/`). Expected: high. Pinned in Task 1's real-git test.
5. **Retargeting a PR from `release/0.0.1` to `production`.** Expected: `ci.yml` and `risk-tier.yml` re-run (`edited` trigger), so a stale green can't carry over. Pinned by the `grep` for `edited` in Task 3, Step 2.
